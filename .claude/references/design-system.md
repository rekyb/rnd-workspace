# Design system reference

The single source of truth for the token and component contract this workspace
draws from — the role `mobbin-sourcing.md` plays for capture. `CLAUDE.md` and
`README.md` link here rather than restating this, so the rules can't drift out of
sync between files.

## Upstream source and the marker contract

The production repo is `https://gitlab.solveeducation.org/solveearn/solveeducation.git`
(default branch `main`, no release tags — see **Access constraints** below).

It materializes its token SSOT (`packages/tokens/tokens.json`) into
`apps/web/app/(frontend)/globals.css`. **The path contains parentheses** — always
resolve it with `Join-Path`/`-LiteralPath`, never `-Path` with wildcard expansion,
or the parenthesis segment breaks glob matching.

The token block sits between two literal marker lines:

```
/* TOKENS:START (generated from packages/tokens/tokens.json by build.mjs — do not edit by hand) */
/* TOKENS:END */
```

`ui-library/tokens.css` is the lines **strictly between** those two markers — byte-
identical to the source, markers themselves excluded. The block contains both a
`:root { … }` rule and a `:root[data-theme="dark"]` rule: **166 CSS custom
properties total**, light and dark together, from one extraction.

## Access constraints

Tested 2026-07-26, not assumed:

| Method | Result |
|---|---|
| `git clone --depth 1` | **Works anonymously.** 29 MB, 2360 files |
| `https://…/-/raw/main/<path>` | HTTP 302 → `/users/sign_in` |
| `git archive --remote=…` | HTTP 404 — GitLab does not serve it |
| `git clone --filter=blob:none` | Clone succeeds; promisor blob fetch fails server-side |

Only `--depth 1` works. `/sync-tokens` therefore shallow-clones to a temporary
location (the session scratchpad, never the workspace), extracts, and discards the
clone. 29 MB per run is acceptable for an occasional command.

## The ui-library/ layout

| File | Origin | Contents |
|---|---|---|
| `tokens.css` | GENERATED | the marker block verbatim — light + dark, 166 custom properties |
| `tokens.json` | GENERATED | the 133 DTCG tokens, kept for drift checking |
| `components.css` | GENERATED | `globals.css` with the marker block, both markers, and the scrub (below) removed |
| `behaviors.js` | HAND-WRITTEN | vanilla behavior for the interactive (non-CSS-only) components |
| `TOKENS.md` | HAND-WRITTEN | digest + provenance — source repo, resolved commit SHA, sync date, counts |
| `COMPONENTS.md` | HAND-WRITTEN | the component catalogue: class contract, behavior, ported status |

**Extract, do not reimplement.** `tokens.css` and `components.css` are sliced from
`globals.css` by marker, never regenerated by re-running `build.mjs`'s own logic.
This guarantees byte-identity with production for `tokens.css`, and means upstream
generator changes never need tracking here.

Before the scrub described in **Disclosure boundary** below, the source slice for
`components.css` was **2515 lines**. Stripping CSS comments shortens that count, so
line count is not a stable invariant across syncs — **239 unique class selectors**
is the load-bearing number to check instead.

**The class contract is identical across React and vanilla.** Production
`<Button variant="pri" block>` and a prototype's `<button class="btn pri block">`
render the same pixels from the same CSS, because the upstream component is a thin
`cx(...)` wrapper with "no new styling introduced."

**`behaviors.js` is the one artifact with no upstream counterpart to diff against**,
so it can silently diverge. Its contract is the class names: if a class disappears
upstream, the `components.css` drift check (`/sync-tokens --check`) catches it even
though the behavior mismatch itself is not automatically detected.

## The overlay rule

Upstream's `themes.json` may override only semantic keys that already exist, so
components re-skin from a token swap alone. `design/<project>/tokens.overlay.css`
follows the same rule: it may **redefine** an existing token name, never
**introduce** a new one. This is the escape hatch for genuine per-project brand
divergence — the generated `ui-library/` files stay read-only otherwise.

Violations are caught by `check-prototype.ps1` rule 3 (an overlay defining a name
absent from `tokens.css` fails), and a hand-edit to any generated file is caught by
running `/sync-tokens --check`, which recomputes both sides from source and exits
non-zero on any divergence — including one introduced by hand rather than by
upstream drift.

## Disclosure boundary

`rnd-workspace` is a **public** GitHub repo. Pushing to it publishes reachable
history, not just the tip commit — anything ever committed stays recoverable even
after a later commit removes it. The boundary:

**Committed:** `ui-library/tokens.css`, `ui-library/tokens.json`, `ui-library/components.css`.
A shipped web product's palette, spacing, and type are already readable in devtools
on the live site, so these are not secrets.

**Never committed:** `packages/tokens/manifest.json` (contains an internal project
UUID, DesignSync references, and rebrand notes), anything from the source repo's
own `.claude/` (`DESIGN.md`, `project-profile.md`, `constitution.md`, `PRIVACY.md`),
and any `apps/` source. Provenance in `TOKENS.md` is recorded as repo URL + commit
SHA + date only — no internal prose.

### Path exclusion is not sufficient — scrub content too

Excluding `manifest.json` by path does **not** keep its contents out. The first real
sync (2026-07-26) proved this: the same internal project UUID, an unannounced
rebrand, an internal PRD name, an internal wiki path, and pre-decisional "RATIFY
before locking" language all reached the public repo through **comments inside the
two permitted files** — a door path exclusion does not cover.

The sync therefore scrubs, deterministically, on every run:

| Output | Scrub | Rationale |
|---|---|---|
| `tokens.css` | none | values only; 0 comments; stays byte-identical |
| `components.css` | strip all CSS comments; remove any external-host `@import` | comments carried the leak; rendering is unaffected |
| `tokens.json` | drop every `$description` field | the top-level one carried the internal prose |

Because the scrub is deterministic and recomputed from source on both sides of the
comparison, `/sync-tokens --check` still detects real drift — the scrub cannot mask
a genuine change, since both the committed file and the freshly-scrubbed source are
compared post-scrub.

**Typography trade-off.** Removing the external `@import` (four Google-hosted font
families) is also a correctness fix — an external font host would violate the
Artifact CSP and the self-contained-file requirement every prototype depends on.
Consequence, stated honestly: `--font-display`, `--font-body`, `--font-mono`, and
`--font-khmer` still *name* those families, so a prototype renders them in whatever
system font the browser falls back to, not the real production typeface.
Typography fidelity is therefore approximate by design, not an oversight.

**Known, accepted limitation.** `components.css` still references
`url("/brand/logo-icon.svg")`, a root-relative path into the production asset
pipeline. It will not resolve inside a prototype and renders as a missing image.
This is intentionally retained rather than patched — `components.css` is generated
and read-only — and it is a local path, not an external host, so it is not a CSP
violation.

## check-prototype rules

`.claude/scripts/check-prototype.ps1` enforces ADR-0003 locally, mirroring
upstream's `gate:no-raw-style` and `gate:css-vars-defined` CI gates, against a built
`standalone.html`. All five rules run and are reported together; any failure blocks
export:

1. **No external hosts** — no `http://` or `https://` in `src`, `href`, or
   `@import`. The Artifact CSP requirement.
2. **No raw style values** — no hex literal and no `px` literal outside
   `ui-library/tokens.css` and `ui-library/components.css`, for any property a token
   covers. Both files are excluded, not just `tokens.css`: `components.css`
   legitimately contains 419 raw `px` values in its own selectors (e.g.
   `border: 1px solid ...`), and excluding only `tokens.css` would flag the entire
   shared component library on every real build.
3. **Every custom property resolves** — every `var(--x)` used resolves to a
   definition in `tokens.css` or the project's `tokens.overlay.css`. **Exempt:**
   any property under the `--radix-*` prefix. Radix UI injects properties such as
   `--radix-select-trigger-width` via inline style at runtime (accordion, select,
   toast primitives), so they are never declared in any CSS file and could never be
   matched against a known list. Accepted cost: a typo inside that prefix (e.g.
   `--radix-slect-trigger-width`) is invisible to this rule forever — the
   alternative, no exemption, permanently fails every real build using those
   primitives, which is worse.
4. **Every class resolves** — every class used in the markup exists in
   `components.css`. This is what makes "fail loudly on an unported component"
   real, rather than silently rendering unstyled markup.
5. **No PII** — the existing capture guardrail applied to prototype content.
   **This rule catches email addresses only.** It is a lint, not a guarantee;
   human review of a prototype is still required before it is shared or
   published, exactly as for a research capture.

## Port on demand

Behaviors are not built up front. `ui-library/behaviors.js` seeds only what the
existing prototypes actually use; the rest of the 42-component catalogue is marked
`not yet ported` in `COMPONENTS.md`. `/design-prototype` **stops** when a PRD calls
for an unported component rather than improvising a lookalike — improvisation is
what produced the existing `--sub` / `--mut` divergence this library exists to end.

`COMPONENTS.md` is the status register: per component, its class contract,
CSS-only-vs-needs-JS classification, and ported status. As of the last sync it
lists 19 CSS-only components (no behavior needed), 4 ported, and 19 not yet
ported — 42 components total, mirroring upstream `apps/web/components/ui/`.
