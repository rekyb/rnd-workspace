# Country Option Hover and Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ensure only the hovered country option receives hover styling and exactly one keyboard-active option receives selected styling.

**Architecture:** Give generated country options a dedicated class and use high-specificity, country-scoped selectors to override the broad legacy dropdown rule. Keep interaction state in the existing `activeCountryIndex` and `aria-selected` flow.

**Tech Stack:** HTML, CSS, vanilla JavaScript, PowerShell, local headless Chrome/CDP

## Global Constraints

- `#country_list` must never receive an interactive hover background, padding, gap, or pointer cursor.
- Hover styling applies only to the `.country-option` under the pointer.
- Selected styling applies only to `.country-option[aria-selected="true"]`.
- Exactly one keyboard-active option is selected; all others remain transparent.
- Preserve vertical stacking, horizontal flag/name layout, filtering, mouse and keyboard selection, ARIA, scrolling, no-arrow combobox, and goal cards.
- Do not modify the shared `.select-items div` rule.
